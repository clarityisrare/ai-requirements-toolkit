# Definition of Ready

A backlog item is **ready** when a team can start work on it without waiting for missing
information. Use this checklist before pulling an item into a sprint or iteration. It is a
gate, not a wish list — if several boxes are unchecked, the item needs more refinement first.

---

## The item is understood

- [ ] Business value / goal is clear
- [ ] User and role are identified
- [ ] Scope is described (what is in and out)
- [ ] Dependencies are identified

## The item is well-formed

- [ ] Written as a user story or clear requirement statement
- [ ] Free of undefined vague terms (see [Ambiguity Detector](../references/ambiguity-detector.md))
- [ ] Uses agreed glossary terms

## The item is testable

- [ ] Acceptance criteria exist
- [ ] Acceptance criteria are measurable and verifiable
- [ ] Relevant non-functional requirements are noted

## The item is feasible

- [ ] Estimable by the team
- [ ] Small enough to complete in one iteration (or a plan to split exists)
- [ ] No unresolved blockers

## The item is traceable

- [ ] Linked to a business objective or epic
- [ ] Source is identified

READY / NOT READY
